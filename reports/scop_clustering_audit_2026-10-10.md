## 2. Patch validation method

The proposal (`scripts/scop_clustering_audit.patch`, 9 hunks over 2 files) could **not** be applied mechanically in this environment: both `git apply` (git 2.46.0.windows.1) and GNU `patch -p1` reject hunks whose preimage was verified **byte-identical** to the current files. Documented evidence:

* Hunk 1's preimage exists exactly once in `scripts/scop_pcncsf_clustering.py` at true line 93, byte-for-byte identical (python byte search: `fb.find(pre) = 3953`, unique occurrence). [V]
* Variants tested — all fail: header line 93 vs 94, with/without the `index` line, with/without `@@`-trailing function text, with/without added trailing context, LF vs CRLF patch bytes, `core.autocrlf` = true/false/input. [V]
* A diff generated by git itself from the same content applies only when paths are rewritten inconsistently; the byte-identical equivalent with normal `a/`, `b/` paths fails. [V]
* Conclusion **[I]:** an environment-specific `git apply`/`patch` quirk (Windows git build), not a content mismatch.

**Decision:** each hunk's *content* was validated against the current files and the loader (`fff/data/scop.py`, `SCOP/*/data.csv`, `runs/` layout), then applied directly with verified edits. The final clean diff of only the validated changes is saved as **`reports/scop_clustering_audit_2026-10-10.patch`** (374 lines, `git diff --check` clean). The original proposal file is left untouched as evidence.

## 4. Loader → embedding → label alignment [V]

* Training loads via `fff.data.load_dataset(tier, ..., condition_on=...)`; with the SCOP CSVs this resolves to **`pdb_id`**, dropna(θ,τ) first, `pd.factorize` first-appearance order. Verified in `fff/data/scop.py` lines 61–90.

## 7. B2 Challenging discrepancy: 0.5155 vs 0.1120 — RESOLVED

* 0.5155 = `results/clustering_hybrid/hybrid_all_g100.csv:89` (`R2 B2-seq`, ward, 194 proteins), produced by the original `scripts/clustering_hybrid.py`. [V]
* 0.1120 = `results/clustering_hybrid_corrected/...` (`R2 B2-normalized-sequential`, ward, 194 proteins), produced by `scripts/clustering_hybrid_corrected.py`. [V]
* Root causes, verified by reading both implementations:
  1. **Raw angles as reals:** the old `b2_features` fed circular means `np.angle(...)` (in [−π,π]) directly as Euclidean features (`[m1, R1, m2_, R2_, R3_, ...]`); the corrected version uses `(cos μ, sin μ, R)` triples.
  2. **Length-proportional feature:** the old 6th feature was `valid_pairs / max(valid_pairs)` — a monotone function of protein length. The corrected version uses the bounded fraction `count / possible` and z-scores every column label-free.
* **[M]** The DIAGNOSTIC row reproduces the old value's regime: length-only ARI on Challenging = 0.5465 ≈ old B2's 0.5155, while corrected B2 = 0.1120.
* **[R]** Treat **0.1120 as the only defensible B2 Challenging number**; the 0.5155 value must not be cited. It is a length-clustering artifact of the superseded feature definition, not a sequential-signal result.
